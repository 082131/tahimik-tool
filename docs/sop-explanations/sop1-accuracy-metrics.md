# Accuracy Metrics: Formula and Implementation Guide

This local guide explains the four performance-accuracy metrics in the thesis manuscript. The manuscript is the methodology authority. Code-level settings may fill in details the manuscript does not explicitly assign, but they must not replace the manuscript's formula or change what the metric measures.

## Shared example

```text
S (noisy source): Kumain nko ng masarappp na adobo.
C (prediction):   Kumain na ako ng masarappp na adobo.
R (reference):    Kumain na ako ng masarap na adobo.
```

The prediction corrects `nko -> na ako`, but wrongly retains `masarappp` instead of `masarap`.

# 1. Generalized Language Understanding Evaluation Plus (GLEU+)

## Purpose

GLEU+ evaluates sentence-level normalization. It rewards word groups in the generated output that agree with the reference, and penalizes word groups that the model wrongly preserved from the noisy source.

## Manuscript formula: modified precision for each n-gram order

$$
P_n^*=
\frac{
\displaystyle\sum_{g\in C_n\cap R_n}\operatorname{count}_{C,R}(g)
-
\displaystyle\sum_{g\in C_n\cap S_n}\max\left(0,\operatorname{count}_{C,S}(g)-\operatorname{count}_{C,R}(g)\right)
}{
\displaystyle\sum_{g\in C_n}\operatorname{count}_{C}(g)
}
$$

The shared-count function is:

$$
\operatorname{count}_{A,B}(g)
=
\min(
\operatorname{count}_{A}(g),
\operatorname{count}_{B}(g)
)
$$

## What each part means

| Formula part | Meaning |
|---|---|
| $n$ | N-gram order. $n=1$ is a word; $n=2$ is a two-word group; $n=3$ is a three-word group; and so on. |
| $g$ | One individual n-gram being checked, such as `masarappp` or `ng masarappp`. |
| $C_n$ | All n-grams in the generated prediction. |
| $R_n$ | All n-grams in the correct reference. |
| $S_n$ | All n-grams in the original noisy source. |
| $C_n\cap R_n$ | N-grams shared by prediction and reference. These are correct generated n-grams. |
| $\sum_{g\in C_n\cap R_n}\operatorname{count}_{C,R}(g)$ | Add the shared count of every n-gram in both prediction and reference. This is the correct-overlap term. |
| $C_n\cap S_n$ | N-grams shared by prediction and noisy source. These require checking because the model may have copied them from the noisy input. |
| $\operatorname{count}_{C,S}(g)-\operatorname{count}_{C,R}(g)$ | Measures whether a source n-gram was retained more often than the reference supports. |
| $\max(0,\ldots)$ | Prevents correct source material from becoming a negative penalty or an extra bonus. It keeps only real penalties. |
| $\sum_{g\in C_n}\operatorname{count}_{C}(g)$ | Total number of generated n-grams of order $n$. This normalizes the score. |

## Sentence explanation

> For each n-gram order, the formula counts all word groups shared by the prediction and the reference, subtracts word groups that were incorrectly retained from the noisy source, and divides the result by all word groups generated by the model.

## Why the `max` is necessary

The second numerator term is:

$$
\sum_{g\in C_n\cap S_n}
\max(0,
\operatorname{count}_{C,S}(g)-
\operatorname{count}_{C,R}(g))
$$

The `max` applies to each n-gram before the penalties are added.

For the correct word `na` in the shared example:

```text
`na` occurs twice in C, once in S, and twice in R.
```

$$
\operatorname{count}_{C,S}(\text{na})=\min(2,1)=1
$$

$$
\operatorname{count}_{C,R}(\text{na})=\min(2,2)=2
$$

$$
\max(0,1-2)=0
$$

Therefore, `na` is not penalized. It is valid to preserve because it also occurs in the reference.

For the incorrect word `masarappp`:

```text
`masarappp` occurs once in C, once in S, and zero times in R.
```

$$
\operatorname{count}_{C,S}(\text{masarappp})=\min(1,1)=1
$$

$$
\operatorname{count}_{C,R}(\text{masarappp})=\min(1,0)=0
$$

$$
\max(0,1-0)=1
$$

Therefore, `masarappp` receives one penalty.

Without `max`, a correct n-gram could produce a negative value and cancel the penalty of an actual error. The formula must penalize wrongly retained noise, not reward correct preservation twice.

## Worked calculation: unigrams

Generated unigrams:

```text
Kumain | na | ako | ng | masarappp | na | adobo.
```

Reference-overlap counts:

```text
Kumain = 1
na     = 2
ako    = 1
ng     = 1
adobo. = 1
```

$$
\sum_{g\in C_1\cap R_1}\operatorname{count}_{C,R}(g)
=1+2+1+1+1=6
$$

The wrongly retained noisy unigram is `masarappp`:

$$
\sum_{g\in C_1\cap S_1}\max(0,\operatorname{count}_{C,S}(g)-\operatorname{count}_{C,R}(g))=1
$$

There are seven generated unigrams:

$$
\sum_{g\in C_1}\operatorname{count}_{C}(g)=7
$$

$$
P_1^*=\frac{6-1}{7}=\frac{5}{7}=0.7143
$$

## Worked calculation: all orders

| Order | Correct reference overlap | Wrong noisy n-grams retained | Total generated n-grams | $P_n^*$ |
|---|---:|---:|---:|---:|
| Unigram | 6 | 1 | 7 | $\frac{6-1}{7}=0.7143$ |
| Bigram | 4 | 2 | 6 | $\frac{4-2}{6}=0.3333$ |
| Trigram | 2 | 2 | 5 | $\frac{2-2}{5}=0$ |
| Four-gram | 1 | 1 | 4 | $\frac{1-1}{4}=0$ |

## Manuscript formula: final GLEU+ score

$$
GLEU^+
=
BP\cdot
\exp\left(
\sum_{n=1}^{K}w_n\log P_n^*
\right)
$$

| Formula part | Meaning |
|---|---|
| $K$ | Maximum n-gram order. |
| $w_n$ | Weight for the n-gram order $n$. |
| $\exp(\sum w_n\log P_n^*)$ | Weighted geometric mean of the modified precisions. It is strict: one zero order makes the total zero. |
| $BP$ | Brevity penalty. It reduces the score when prediction is shorter than the reference. |

The manuscript's brevity penalty is:

$$
BP=
\begin{cases}
1, & c>r\\[4pt]
e^{1-r/c}, & c\le r
\end{cases}
$$

where $c$ is generated-output length and $r$ is reference-output length.

For the shared example, $c=7$ and $r=7$:

$$
BP=e^{1-7/7}=1
$$

If $K=4$ with equal weights, the shared example gives:

$$
GLEU^+
=
1\times\sqrt[4]{0.7143\times0.3333\times0\times0}=0
$$

## Manuscript-to-code alignment

`src/evaluation/metrics.py` implements the manuscript formula: modified
precision, a source-copy penalty, an equal-weight geometric mean, and brevity
penalty. A non-positive modified precision returns GLEU+ = 0 because its
logarithm is undefined.

### Operational settings that code may add

These settings make the manuscript formula executable without changing its core method:

```text
K = 4
w1 = w2 = w3 = w4 = 1/4
n-grams = whitespace-tokenized word n-grams
c and r = word-token counts
multiset counts = Counter, not a plain set
```

### Concern: zero or negative modified precision

The manuscript formula contains $\log P_n^*$, but $\log(0)$ and $\log(\text{negative})$ are undefined. The manuscript does not define this edge case.

The strict manuscript-preserving code rule is:

```text
If any P*n is less than or equal to zero, return final GLEU+ = 0.
```

This is strict, but it does not change the stated formula. Add-one smoothing would make partial scores more differentiated, but it would be a numerical extension of the manuscript formula and should not be silently presented as the original formula.

# 2. Character-level F-score (chrF)

## Purpose

chrF measures character-level similarity between the generated output and the reference. It gives partial credit when a generated word is close to the reference but not an exact match.

## Manuscript formula

$$
chrF_\beta
=
\frac{
(1+\beta^2)(chrP)(chrR)
}{
\beta^2(chrP)+chrR
}
$$

## What each part means

| Formula part | Meaning |
|---|---|
| $chrP$ | **No-extra-groups check:** among all character groups in the prediction, what proportion is also correct according to the reference? |
| $chrR$ | **No-missing-groups check:** among all character groups required by the reference, what proportion did the prediction include? |
| $\beta$ | Recall-weighting parameter. A larger value gives more importance to recall. |
| $(1+\beta^2)(chrP)(chrR)$ | Combines character precision and recall. |
| $\beta^2(chrP)+chrR$ | Normalizes the combined result into an F-score. |

## The formulas for chrP and chrR

For one character n-gram length $n$ (for example, $n=3$ means character trigrams):

$$
chrP_n =
\frac{\text{number of prediction character n-grams also found in the reference}}
{\text{total number of character n-grams in the prediction}}
$$

$$
chrR_n =
\frac{\text{number of reference character n-grams also found in the prediction}}
{\text{total number of character n-grams in the reference}}
$$

The numerator is the same shared character n-gram count in both formulas. The difference is the denominator:

| If you divide by... | You are asking... | Metric |
|---|---|---|
| Character groups produced by the model | “Did the model add incorrect character groups?” | $chrP$ |
| Character groups required by the reference | “Did the model miss required character groups?” | $chrR$ |

The implementation calculates these overlaps for character n-gram orders 1 through 6, then SacreBLEU combines the configured orders into $chrP$ and $chrR$ before applying the manuscript's chrF formula.

## Sentence explanation

> chrF compares overlapping groups of characters between the prediction and reference, then combines character precision and character recall into one score. It gives partial credit when the predicted spelling is close to the correct spelling.

## Example

```text
Prediction: masarappp
Reference:  masarap
```

`masarappp` is not an exact word match, but it shares many characters and character groups with `masarap`.

For example, shared character trigrams include:

```text
mas
asa
sar
ara
rap
```

Therefore, chrF remains relatively high even though the word is not completely correct.

Using the current code configuration, the shared full-sentence example produces approximately:

$$
chrF=91.61
$$

This high result means the prediction is character-wise very similar to the reference. It does **not** mean every complete word is correct.

## Manuscript-to-code alignment

The current code uses SacreBLEU chrF with:

```python
CHRF(char_order=6, word_order=0)
```

This means character n-grams up to order six are used and word n-grams are excluded. SacreBLEU's default $\beta$ is 2, giving recall greater weight.

These are reasonable operational settings, but the manuscript does not explicitly state:

```text
character n-gram maximum order
beta value
whether word n-grams are included
whether corpus chrF or mean sentence chrF is reported
score scale: raw 0–1 or percentage 0–100
```

`compute_all` reports corpus chrF on SacreBLEU's 0–100 scale, while the
sentence-level values are retained only for paired bootstrap resampling.

# 3. Error Reduction Rate (ERR)

## Purpose

ERR measures whether the model improved the noisy input. It compares the model against a Leave-As-Is baseline, where the original noisy sentence is treated as the output.

## Manuscript formula

$$
ERR
=
\frac{
Accuracy_{system}-Accuracy_{leave\text{-}as\text{-}is}
}{
1.0-Accuracy_{leave\text{-}as\text{-}is}
}
$$

The manuscript defines:

$$
Accuracy_{system}
=
\frac{
\text{number of correctly normalized tokens in the system output}
}{
\text{total number of evaluated tokens}
}
$$

$$
Accuracy_{leave\text{-}as\text{-}is}
=
\frac{
\text{number of tokens already correct when noisy input is unchanged}
}{
\text{total number of evaluated tokens}
}
$$

## What each part means

| Formula part | Meaning |
|---|---|
| $Accuracy_{system}$ | Proportion of evaluated tokens the model normalized correctly. |
| $Accuracy_{leave-as-is}$ | Proportion of tokens already correct if the noisy input is not changed at all. |
| Numerator | The model's improvement over doing nothing. |
| Denominator | The amount of error that was available to correct. |
| ERR = 1 | The model corrected all possible remaining error. |
| ERR = 0 | The model did not improve over Leave-As-Is. |
| ERR < 0 | The model made the output worse than Leave-As-Is. |

## Sentence explanation

> ERR measures how much the model improved the noisy input. It compares the system's token accuracy with the accuracy obtained by leaving the noisy sentence unchanged, then expresses the gain relative to the errors that were available to fix.

## Example

Suppose a sentence contains ten evaluated tokens.

```text
Leave-As-Is correctly matches 6 of 10 tokens.
System output correctly matches 9 of 10 tokens.
```

$$
Accuracy_{leave-as-is}=\frac{6}{10}=0.60
$$

$$
Accuracy_{system}=\frac{9}{10}=0.90
$$

$$
ERR=\frac{0.90-0.60}{1.0-0.60}
$$

$$
ERR=\frac{0.30}{0.40}=0.75
$$

The model corrected 75% of the error that was originally available to correct.

## Manuscript-to-code alignment and cited-study basis

The ERR formula in the manuscript is consistent with the definition used by the cited MultiLexNorm normalization study. That study defines ERR as word-level accuracy normalized by the percentage of words that need normalization. It uses the Leave-As-Is output as the baseline, which therefore has ERR = 0. The cited study does **not** define ERR as a character-edit-distance improvement.

The implementation follows this definition. It case-folds whitespace-separated
tokens while retaining punctuation, aligns token sequences before counting
correct tokens, pools corpus token totals before division, and keeps
sentence-level ERR values only for paired bootstrap resampling.

```text
(character edit distance of noisy input to reference
 - character edit distance of prediction to reference)
/ character edit distance of noisy input to reference
```

The implemented calculation is:

```text
accuracy_system       = correctly normalized evaluation words / total evaluation words
accuracy_leave_as_is  = words already correct in the unchanged noisy input / total evaluation words
ERR = (accuracy_system - accuracy_leave_as_is)
      / (1 - accuracy_leave_as_is)
```

Because a sentence-level model may insert, delete, split, or merge words, add one reproducible preprocessing rule: align each prediction and reference word sequence before counting correctly matched words. Word-level Levenshtein alignment may be used for this alignment step, but its distance must not replace the ERR formula. The metric remains an accuracy-based ERR, not an edit-distance ERR.

ERR remains a ratio; Leave-As-Is produces ERR = 0 when errors are available to
correct. The manuscript's conflicting edit-distance prose remains unchanged in
the DOCX by author instruction.

# 4. Alpha-word Accuracy

## Purpose

Alpha-word Accuracy checks exact correctness of alphabetic word tokens. It excludes non-alphabetic items such as numbers, emojis, URLs, mentions, punctuation, and alphanumeric forms.

## Manuscript formula

$$
Alpha\text{-}word\ Accuracy
=
\frac{T_s}{T_g}\times100
$$

## What each part means

| Formula part | Meaning |
|---|---|
| $T_s$ | Number of reference alphabetic-word tokens correctly predicted by the system output. |
| $T_g$ | Total number of alphabetic-word tokens in the reference normalized output. |
| $T_s/T_g$ | Proportion of expected alphabetic words that the model predicted correctly. |
| $\times100$ | Converts the ratio into a percentage. |

## Sentence explanation

> Alpha-word Accuracy counts how many alphabetic words from the correct reference were predicted exactly by the model, divides that number by all alphabetic words expected in the reference, and reports the result as a percentage.

## Example

```text
Prediction: Kumain na ako ng masarappp na adobo.
Reference:  Kumain na ako ng masarap na adobo.
```

Reference alpha-word tokens:

```text
kumain | na | ako | ng | masarap | na | adobo
```

There are seven expected alphabetic words:

$$
T_g=7
$$

Correctly predicted words are:

```text
kumain | na | ako | ng | na | adobo
```

Therefore:

$$
T_s=6
$$

$$
Alpha\text{-}word\ Accuracy
=\frac{6}{7}\times100
=85.71\%
$$

## Manuscript-to-code alignment concern

The implementation uses sequence-aligned word-level Levenshtein matching to
derive $T_s$, then reports the manuscript's $T_s/T_g\times100$ percentage.

$$
\max\left(0,1-\frac{word\ edit\ distance}{reference\ word\ count}\right)
$$

This supplies a reproducible rule for insertions, deletions, and substitutions
without replacing the manuscript formula.

## Recommended clarification to add under the manuscript formula

The manuscript's formula should remain the definition of the metric. Add the following as its **calculation procedure**, rather than replacing the formula:

> Before Alpha-word Accuracy is computed, the system extracts alphabetic words, converts them to lowercase, and removes surrounding punctuation. The predicted and reference word sequences are then aligned using word-level Levenshtein alignment. Each substitution, insertion, or deletion is treated as one word-level error. For a sentence with $T_g$ reference alphabetic words and word-level edit distance $d_w$, the effective number of correctly predicted reference words is $T_s = \max(0, T_g-d_w)$. Alpha-word Accuracy is then computed as $T_s/T_g \times 100$.

This preserves the manuscript's idea: **correct alphabetic words divided by all expected alphabetic words.** It only supplies the missing rule for deciding what “correctly predicted” means when word sequences are not identical.

### Why sequence matters

Sequence matters because words must appear in the correct order to be a correct normalization. For example:

```text
Prediction: Kumain ako na ng masarap na adobo.
Reference:  Kumain na ako ng masarap na adobo.
```

The words `na` and `ako` both occur, but their order is reversed. A count-only method could incorrectly give full credit because every word is present. Word-level Levenshtein alignment recognizes that the sequence differs, so the score is lower.

At the same time, alignment avoids a different unfair result. If one extra word appears at the start, it does not make every later word appear wrong merely because their positions shifted.

### Why this is preferable to counting shared words only

Using only shared word counts, such as a bag-of-words overlap, would ignore word order and may give 100% to a scrambled sentence. Using the longest common subsequence alone would preserve order, but it would not penalize an unnecessary inserted word. The current word-level edit-distance approach handles all three relevant normalization errors:

| Output problem | Alignment operation | Effect on $T_s$ |
|---|---|---|
| Incorrect word | Substitution | Lose one credit |
| Missing reference word | Deletion | Lose one credit |
| Unnecessary generated word | Insertion | Lose one credit |
| Reversed or displaced word | Usually a deletion plus an insertion, or substitutions | Lose credit because the sequence is wrong |

### Example: an extra generated word

```text
Prediction: Hoy kumain na ako ng masarap na adobo.
Reference:      Kumain na ako ng masarap na adobo.
```

There are $T_g=7$ reference alphabetic words. The extra `Hoy` is one insertion, so $d_w=1$ and the effective correct-word count is $T_s=7-1=6$.

$$
Alpha\text{-}word\ Accuracy
=\frac{6}{7}\times100
=85.71\%
$$

This is the behavior of the current code. It prevents an output with an unnecessary word from receiving perfect accuracy.

### Small code/manuscript alignment items to state explicitly

The current implementation already uses word-level Levenshtein distance, but the methodology/code documentation should explicitly state these details:

1. **Sequence rule:** use word-level Levenshtein alignment as described above.
2. **Score scale:** code returns the manuscript's 0–100 percentage.
3. **Dataset aggregation:** reported scores pool $T_s$ and $T_g$ across the corpus; sentence-level percentages are retained for paired bootstrap testing.
4. **Token handling:** lowercase words and strip surrounding punctuation before retaining alphabetic tokens; exclude numbers, URLs, emojis, and alphanumeric tokens.

Example:

```text
Prediction: Hoy kumain na ako ng masarap na adobo.
Reference:      Kumain na ako ng masarap na adobo.
```

The current code penalizes the inserted word `Hoy`, producing a score below 100%. The manuscript formula does not explicitly state how extra words or word alignment should be handled.

The following are valid implementation details if documented consistently:

```text
case handling: convert words to lowercase
punctuation handling: strip surrounding punctuation
word alignment: use sequence alignment before counting Ts
extra predicted words: treat as an alignment error
score scale: return 0–100 to match the manuscript
```

However, the code should ultimately calculate and report the manuscript's $T_s/T_g\times100$ definition, not describe a different metric under the same name.

# Final implementation checklist

Before final experiments, verify that every metric has one declared formula and one matching implementation.

| Metric | Core manuscript requirement | Main current concern |
|---|---|---|
| GLEU+ | Source-aware modified precision, geometric mean, brevity penalty | Current code uses a different arithmetic formula and lacks BP. |
| chrF | Character precision/recall F-score | Parameters and aggregation must be documented consistently. |
| ERR | Improvement relative to Leave-As-Is | Manuscript prose uses edit distance while displayed formula uses token accuracy. |
| Alpha-word Accuracy | $T_s/T_g\times100$ exact alpha-word correctness | Current Levenshtein score may differ when insertions/deletions occur. |

The central rule is:

> The manuscript defines what each metric is. Code may add reproducible operational settings, but it must not silently calculate a different metric and report it under the manuscript's metric name.
